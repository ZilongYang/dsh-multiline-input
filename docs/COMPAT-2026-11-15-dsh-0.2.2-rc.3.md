## 结论

**✅ 不需要为 rc.3 改任何功能代码。** 本插件依赖的 composer / dock / shortcuts / locale / 设置槽契约在 rc.3 上逐个在位；升级指南里也**没有 rc.2 / rc.3 的条目**（最新一节是 `v0.2.2-rc.1`，共 19 项），说明这两次发版没有需要迁移的破坏性改动。

0.2.2 里要做的只是**元数据与文档**：`dsh.compatibility.dshReleases` 补 rc.2 / rc.3，`engines.dsh` 不变（判定带 `includePrerelease`，rc.3 可过）。

## 二、核对手法（可复现）

1. 版本确认：

   ```sh
   ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" -e "console.log(JSON.parse(require('node:fs').readFileSync(process.env.DSH_INSTALL_DIR+'/package.json','utf8')).version)"
   # 0.2.2-rc.3
   ```

2. 升级指南索引（只打印标题行，避免整文件读入）：

   ```sh
   ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" -e "require('node:fs').readFileSync(process.env.DSH_INSTALL_DIR+'/docs/upgrade-guide/README.md','utf8').split(/\r?\n/).forEach((l,i)=>{ if(l.startsWith('## ')) console.log(i+1,l) })"
   # 最新一节是 ## v0.2.2-rc.1（19 项），没有 rc.2 / rc.3
   ```

3. 构建产物里逐锚点计数（`require.resolve` 解析到 `@deepseek-ai/dsh-client-ui-conversation` 等包，再用字符串计数 + 上下文窗口确认语义）。

4. 运行时佐证：`~/.dsh/logs/desktop-next.log` 中本插件只有模块 URL 列表命中，**没有 `[dsh-multiline-input]` 相关告警或异常**（对比：`@deepseek-ai/dsh-hooks-claude-code@0.2.2-rc.1` 因 peer 钉死 rc.1 被宿主停用，`dsh-better-sidebar` 报 `patch: entry not found` —— 都发生在别人的插件上）。

## 三、rc.3 上观察到的两个新行为（都不影响本插件，供参考）

1. **单例槽重复注册现在会抛错**：调用形如 `single slot "sidebar.workspaces.directoryFlow" already has a registration at priority -100 ... register at a different priority to shadow it`。本插件注册的三个槽分别是 `list`（dock）、`keyed`（`plugins.row.config`，key 唯一）与 `list`（`settings.section`，id 唯一），不触及该规则。
2. **`BundleInfo.update` 取代 `updatable`**（升级指南第 12 项）：只影响插件管理器的更新按钮，与本插件的运行时行为无关。
