## 1. 目标与验收标准

**目标**：纯客户端第三方插件 `dsh-ml-input`，不改 DSH 源码，把对话输入框在「单行（现状）/ 多行」之间循环切换：

1. 输入框右上角显示当前生效的切换快捷键（默认 `Ctrl+E`）+「多行输入」；输入框为空时显示，有草稿/附件时隐藏，避免压字。
2. 按快捷键循环：单行 → 多行 → 单行。
3. 多行模式默认高度 **4 行**（落在需求的 3–5 行区间），内容变多继续长高，到原生 336px 上限后滚动。
4. 多行模式下 **Enter 换行、Shift+Enter 提交**；单行模式保持 DSH 现状（Enter 提交、Shift+Enter 换行）。
5. 快捷键可在官方「设置 → 通用 → 快捷键」里改绑，提示实时跟随。

**验收标准**：

- 空输入右上角出现 `Ctrl+E 多行输入`；输入后消失，清空重现。
- `Ctrl+E` 在编辑器内、页面空白处都能切换；设置/其它输入框里不抢键。
- 多行最小高度 4 行；切回单行立即恢复；草稿不丢。
- 多行：Enter 换行（可撤销）、Shift+Enter 发送；`Cmd/Ctrl+Enter` 仍是加速提交；`/`、`@` 菜单打开时 Enter 仍是选中菜单项；输入法候选态不误触。
- 刷新后模式保持；设置里改键后提示立即变化、冲突有官方提示。
- 禁用/卸载后无 `<html data-dsh-ml-input>`、无 `<style>`、无键盘监听、无快捷键命令残留。

## 4. 实现设计

### 4.1 清单与 Host 半

```json
{
  "name": "dsh-ml-input",
  "version": "0.1.0",
  "type": "module",
  "exports": { ".": "./index.js", "./client": "./client.js",
               "./package.json": "./package.json", "./locale/*.json": "./locale/*.json" },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "platform": "web",
      "immediately": true,
      "inject": ["@deepseek-ai/dsh-client-locale", "@deepseek-ai/dsh-client-ui-conversation"]
    },
    "compatibility": { "dsh": ">=0.2.1-rc.3 <0.3.0-0" }
  }
}
```

`cordis.patch.yml`：

```yaml
- insert:
    - id: ml-input
      name: 'dsh-ml-input'
```

`index.js` 只导出 `name` 与空的 `apply(){}`，让包成为可安装/启停的 bundle row；客户端半由 `dsh.client` 自动发现。

### 4.2 模式状态

- `'single' | 'multi'`，默认 `single`；`localStorage['dsh-ml-input.mode.v1']`（读写 try/catch，失败退化内存态）。
- 生效：`<html data-dsh-ml-input="multi">`，单行时移除；`apply()` 时同步设置，卸载时清理。
- 模块级 store：`getSnapshot / subscribe / toggle`，提示组件用 `useSyncExternalStore` 订阅（与 dsh-session-titler 同款）。
- 切换不清空草稿、不抢焦点；点提示时 `mousedown.preventDefault()` 保焦点。

### 4.3 快捷键（官方命令，可编辑）

- id `ml-input.toggle`（满足 `a.b` 持久化格式）；label zh「切换多行输入」/ en「Toggle multiline input」；aliases 含「多行输入 / 单行输入 / multiline / ml-input」。
- 默认：`desktop:macos|windows|linux` = `{code:'KeyE', modifiers:['control']}`（显示 `Ctrl+E`）；`web:macos|windows` = `{code:'KeyE', modifiers:['primary','shift']}`（Web 白名单允许）；`web:linux` 不设默认。
- `regions: ['page','editable']`，`modals: []`。
- `resolve(context)`：`modal !== null` → pass；目标在 composer 之外的输入框 → pass（保留系统/浏览器原生 Ctrl+E）；否则 handled → `toggle()`。
- 注册放在 `ctx.inject(['shortcuts'], scope => scope.effect(() => scope.shortcuts.register(...)))`，try/catch：与其它插件默认组合冲突时降级为「点击切换」+ console.warn，不让插件激活失败。
- 修改入口即官方设置：注册后自动出现在「设置 → 通用 → 快捷键」弹窗（可搜索、录制、冲突提示、按设备持久化）。
- 提示键位来自 `ctx.shortcuts.catalog` 快照，自绘格式（control→Ctrl、meta→Cmd、alt→Alt、shift→Shift，code 去 `Key` 前缀），macOS 也显示 `Ctrl+E`。

### 4.4 右上角提示

- 座位 `conversation.input.overlay`（list，`order:10`），渲染 `<button class="dml-hint">`。
- 可见性用标准 hook `useInput(s => s.draft === '' && s.attachmentIds.length === 0)`，与 `showPlaceholder` 语义一致；不做订阅机制。
- 内容：`<span class="dml-key">Ctrl+E</span><span class="dml-label">多行输入</span>`；多行模式加 `<span class="dml-meta">Shift+Enter 提交</span>`，label 变「单行输入」。
- 定位 `position:absolute; top:8px; right:12px`（相对 `[data-composer-overlay]`），12px 字，key 用 `--dsw-alias-label-secondary`、label 用 `--dsw-alias-label-tertiary`。
- 点击切换；`click.stopPropagation()` 防止 hero 卡片触发工作区选择；`title` 说明可在设置中修改。

### 4.5 多行高度

```css
html[data-dsh-ml-input="multi"] [data-composer-card] [data-composer-input] {
  min-height: calc(4 * 1lh + 8px);  /* 4 行正文 + 上下 padding；不支持 lh 时回退 calc(4 * 24px + 8px) */
}
```

只依赖 `data-*` 锚点；specificity 高于 `.input` 与 hero 的 52px；不提高 336px 的滚动上限（4 行起步、最多约 14 行后滚动）。

### 4.6 Enter / Shift+Enter

document 捕获阶段 keydown（`ctx.effect` 卸载），全部满足才接管：多行模式；`key==='Enter'` 且无 `ctrl/meta/alt`；非输入法（`isComposing` / `keyCode 229`）；目标在 `[data-composer-card]` 内且是 `[data-composer-input][contenteditable="true"]`；`data-phase === 'plain'`；覆盖层内无 `[role="listbox"]`。

接管：`preventDefault + stopPropagation`，向编辑器派发翻转 `shiftKey` 的合成 `KeyboardEvent`（打标防递归）：

- Enter → 派发 Shift+Enter：走 DSH 自己的换行分支（LineBreak，进 undo）；
- Shift+Enter → 派发 Enter：走 DSH 自己的提交分支（busy-enter / canSubmit / 菜单仲裁全部保留）。

兜底（实机若合成事件不生效）：改用 `inputActions.captureInsertion()` + `insertText('\n', span)` 换行、`inputActions.submit()` 提交，判定条件不变。

## 5. 边界与失败模式

| 场景 | 处理 |
|---|---|
| 输入法候选态 Enter | 放行 |
| `/`、`@` 菜单打开 | 检测 `[role=listbox]`，放行 |
| 命令 claim / 提交中 | `data-phase !== 'plain'` 放行 |
| Cmd/Ctrl+Enter、Alt+Enter | 放行 |
| 其它输入框里的 Ctrl+E | resolve 返回 pass |
| 设置弹窗/录制中 | `modal !== null` → pass |
| 快捷键冲突 | catch 降级，提示仍可点 |
| 快捷键被清空 | 提示只显示文案 |
| 无 shortcuts 服务 | `ctx.inject` 不触发，其余功能照常 |
| localStorage 不可用 | 内存态 |
| 两个 composer | 高度统一生效，提示各自渲染，监听一份 |
| 只读 composer | `contenteditable="true"` 才接管 |
| DSH DOM 锚点变化 | 首次挂载自检，缺锚点只 warn 一次，不崩 |
| 卸载 | 移除 style / 属性 / 监听 / 命令 |

## 实施偏差（事后补记）

> 本节为实施后补记，与上方计划原文分开看。

1. **目标 profile 判断错误**：计划里写「当前 `main`」，实际当前运行的是 **DeepSeek Harness.app + `desktop` profile**。依据：运行中的 Host 进程 cwd 与打开的 `~/.dsh/profiles/desktop/package.json`、`cordis.patch.yml`；本会话可用的 zotero / im / univer 工具只出现在 desktop 的 bundle 列表；desktop profile 的 `.plugin-manager` 日志显示最近的本地 link 安装。`main` 属于同时运行的 DSH NEXT（监听 58501，日志 `desktop-next.log`），与当前 GUI 不是同一实例。

2. **安装方式**：`dsh plugin --profile desktop add ...` 被应用独占拒绝（`profile "desktop" is managed exclusively by the Electron application`）。改为等价的手动 link：用应用自带的 pnpm 11.28.5 在 desktop profile 执行 `pnpm add link:/Users/zilong/zWork/ai/zl-plugins/dsh-ml-input`，并把 `dsh-ml-input` 追加进 `dsh.profile.bundles`。profile 的 `patchReload: live` 让 HMR 监听 `package.json`，改动后自动 reconcile。

3. **Host 行激活验证**：曾临时在 `index.js` 的 `apply()` 里写文件哨兵，并在 profile 补丁里临时加 `- id: ml-input` 的 disable/enable 行强制重载；哨兵于 `2026-10-27T16:30:37Z` 出现，证明 Host 已组合并激活插件行。随后已删除哨兵、恢复补丁文件并还原 `index.js`。

4. **浏览器半验证**：曾临时在 `apply()` 写 `localStorage['dsh-ml-input.selfcheck']`，在 Electron 的 LevelDB 中读到该键，证明客户端 bundle 已加载且 `apply()` 真正执行；随后用一次性 removeItem 版本清除并恢复最终代码。

5. 实现与计划一致：单文件手写 `client.js`、`conversation.input.overlay` 提示、`ctx.shortcuts` 命令、捕获阶段翻转 `shiftKey` 的 Enter 接管、`data-*` 锚点。（计划里“用 `useInput` 判断空草稿”在后续样式调整中已移除，提示改为常驻。）

6. **开发热更新更正**：计划第 7 节写「改 client.js 刷新页面即可」，实测不成立——HMR 默认忽略 `**/node_modules`（`packages/boot/hmr/src/index.ts`），链接安装的 `client.js` 改动不会被 `rebuilt()` 拾取。实际做法：在插件页把本插件关/开一次（或重启应用）触发客户端 bundle 重组，再刷新页面；`package.json` / 补丁文件的改动仍会被 profile 监听自动 reconcile。README 已同步。

7. **验收后的用户调整（2026-10-28）**：按子龙反馈——① 桌面默认键从字面 `Control+E` 改为 `primary+KeyE`（macOS 显示并生效为 `Cmd+E`，Windows/Linux 为 `Ctrl+E`）；② 提示改为**常驻**，不再随输入隐藏。
