## 1. 目标与验收标准

**目标**：在现有单行 / 多行切换插件上补齐 0.2.0 的交互能力，不改变 0.1.1 已验收的行为：

1. tab 右侧新增收起按钮，收起后变成输入卡片上沿右对齐的 8px 细线；点击细线恢复 tab；状态按设备持久化；`Cmd/Ctrl+E` 收起后仍生效。
2. 每轮**被 Host 接受**的普通消息文字写入设备侧输入历史（全局、去重、限量、可清空）；`/` 命令、空提交、失败/被拒提交不记录。
3. 输入框内：单行模式 `↑` / `↓`，多行模式 `Shift+↑` / `Shift+↓`，按最近提交顺序循环替换；首次 `↑` 保存当前草稿，`Esc` 或在新条目上再按 `↓` 还原并退出；浏览时 tab 显示「历史 n/m」。
4. 全部逻辑以 DSH 0.2.1-rc.5 的公开契约与 DOM 锚点为准回归；`sending` 相位不拦截、不误记。
5. 单测、语法检查、打包清单全绿；文档与版本号同步。

**验收标准**：

- 收起后输入区高度实际减少（桌面 dock 态约 16px），刷新后保持收起；点击细线恢复；展开态与原 0.1.1 观感一致。
- 收起状态下 `Cmd+E` 仍切换模式（高度变化可见），不报错。
- 提交一条消息后清空输入框，按 `↑` 出现该文字；连续 `↑` 逐条向前，到最旧后回到最新；`↓` 反向；从最新再按 `↓` 或按 `Esc` 还原浏览前草稿。
- 多行模式下 `Shift+↑` / `Shift+↓` 浏览历史，普通 `↑` / `↓` 仍是原生光标移动；单行模式普通 `↑` / `↓` 浏览。
- 菜单打开、输入法组合态、`/` 命令 claim、`adjudicating` / `submitting` / `sending` 相位下，方向键完全交还原有逻辑。
- 断网 / Host 拒绝导致的失败提交不进入历史；之后成功提交的同一文字正常进入。
- 禁用 / 卸载插件后无监听、无样式、无 DOM 残留；历史数据保留，重新启用后可用。
- 0.1.1 的 Enter/Shift+Enter、多行高度、模式持久化、快捷键改绑全部不回归。

## 3. 实现设计

全部改动集中在 `client.js`，不新增构建、不新增 Host 服务、不改 `index.js`。

### 3.1 常量与本地数据结构

新增：

```js
const HINT_STORAGE_KEY = 'dsh-multiline-input.hint.v1'        // 'collapsed' | 'expanded'
const HISTORY_STORAGE_KEY = 'dsh-multiline-input.history.v1'
const CLEAR_HISTORY_COMMAND_ID = 'multiline-input.clear-history'
const HISTORY_MAX_ENTRIES = 200
const HISTORY_MAX_TOTAL_CHARS = 100000
const HISTORY_MAX_ENTRY_CHARS = 16000
```

历史存储形如：

```json
{ "version": 1, "entries": [ { "text": "…", "at": 1761734000000 } ] }
```

- 读取容错：非法 JSON、错误 shape、旧版纯数组都归一为 `{version:1, entries:[]}` 或尽量可用的条目；
- 写入失败（隐私模式 / 配额）只降级为内存态，并 `console.warn` 一次；
- 与现有 `MODE_STORAGE_KEY` 共用 `dsh-multiline-input.` 前缀；
- 历史是设备本地明文（不含加密），README 明示，并提供清空入口。

### 3.2 输入历史记录（Host 接受后才落库）

在 `MultiLineHint` 组件内利用标准 props：`useInput`、`useSession`、`inputActions`（session-scoped slot 已由 DSH 注入，参考已装 `dsh-session-titler` 的用法）。

记录流程：

1. 订阅 `useInput(s => s.phase)` 与 `useInput(s => s.draft)`。
2. 当 `phase` 进入 `sending` 且当前没有待确认捕获时，把 `draft` 记为 `pendingText`（这正是 Enter 时的剪贴板投影，含引用 chip 的显示文本）。
3. 订阅 `useSession(s => s.pendingSubmissions)`；用 `requestId` 集合判断是否出现**新**条目。出现新条目且 `pendingText !== null` → 调用 `historyStore.record(pendingText, Date.now())` 并清空捕获。
4. 下一次 `sending` 若仍有未确认捕获，用新草稿替换（说明上一条失败/未确认，不落库）。
5. 组件卸载（切会话）时丢弃未确认捕获。
6. 只处理 `sending`；`adjudicating` / `submitting`（`/` 命令）天然不进入此分支，因此命令不记录。
7. 记录前清洗：`trim()` 后为空 → 跳过；以 `/` 开头 → 跳过；长度 > `HISTORY_MAX_ENTRY_CHARS` → 跳过；与已有条目完全相同 → 移到最前（去重，不产生重复）。
8. 每次记录后按条数 / 总字符数淘汰最旧条目，再持久化。

纯函数（导出到 `__test`）：

- `sanitizeHistory(raw)` → `entries`
- `recordHistory(entries, text, at, limits)` → `entries`
- `trimHistory(entries, limits)` → `entries`
- `readHistory(store)` / `writeHistory(store, entries)`
- `advanceCapture(state, observation)` → `{ state, commit }`（`observation = { phase, draft, newPending }`）

> 为什么不直接记录 `pendingSubmissions[].text`：那是序列化后的模型文本（引用展开、引用块改写），与用户输入框里看到的文字不同；只用它做「已接受」信号，正文取 `draftSnapshot` 的投影。

### 3.3 ↑ / ↓ 浏览历史

在 `MultiLineHint` 内注册 document 捕获阶段 `keydown`（组件卸载即移除），并用 `useRef` 持有最新 `{ phase, draft, mode, browsing }`，避免每次输入重绑。

纯函数：

```js
resolveBrowseIntent(input) -> 'older' | 'newer' | 'exit' | null
nextBrowseIndex(index, total, direction) -> number
```

判定（全部满足才接管）：

- 目标在 `[data-composer-card]` 内，且是 `[data-composer-input][contenteditable="true"]`；
- `phase === 'plain'`；覆盖层内无 `[role="listbox"]`；非输入法组合态（`isComposing` / `keyCode 229`）；
- 无 `Ctrl` / `Meta` / `Alt`；
- 单行模式：`ArrowUp` / `ArrowDown`（不按 Shift）；多行模式：`Shift+ArrowUp` / `Shift+ArrowDown`（不带 Shift 放行给原生光标/选择）。

行为：

- `ArrowUp`（非浏览态）：保存当前草稿到 `browse.saved`，索引 0，替换为最新一条；历史为空则放行。
- `ArrowUp`（浏览态）：`index + 1`，到最旧后回到最新（循环）。
- `ArrowDown`（浏览态）：`index > 0` 时 `index - 1`；`index === 0` 时还原 `saved` 并退出（shell 语义）。
- `Esc`（浏览态）：还原 `saved` 并退出；非浏览态放行。
- 浏览态下任何其他按键、`paste` / `cut`：退出浏览但**保留当前文字**；提交（进入 `sending`）也退出并清空 `saved`。
- 替换草稿走 `inputActions.setDraft(text)`，随后 `inputActions.persistDraft()`；不直接改 DOM，保护 Lexical 撤销 / 输入法 / 引用 chip 面。
- 接管时 `preventDefault + stopPropagation`，避免 Lexical 再处理方向键。
- 浏览时 tab 的 label 显示 `历史 {n}/{m}`（n = index + 1），快捷键盘位仍显示；退出后恢复模式文案。

`browseStore` 为模块级快照 store：`{ active: boolean, index: number, saved: string }`，供 tab 订阅与监听器读取。

### 3.4 tab 收起

- 新增 `hintStore`（`collapsed: boolean`），读写 `HINT_STORAGE_KEY`；默认展开。
- 展开态：tab 内主按钮（模式切换）右侧新增独立收起按钮（内联 chevron-down SVG，20×20 命中区），`aria-label` / `title`，`onMouseDown` preventDefault 保焦点，`stopPropagation` 避免触发展开/切模式。
- 收起态：整行 `.dmi-hint-row.dmi-hint-row-collapsed` 高度 **8px**，保持与卡片同列、右对齐、同一 `padding-right`；行内一个 `.dmi-hint-line` 按钮：宽 40px、高 2px、圆角、`--dsw-alias-border-l3`，hover 变宽到 56px 并改用 `--dsw-alias-label-secondary`，带 `title` 与 `aria-expanded="false"`；点击恢复 tab。
- `margin-bottom` 仍为 `calc(-1 * var(--dmi-stack-gap))`：dock 态净占 2px、hero 态净占 0px，输入区比展开态回收约 16px；不会压住卡片上沿。
- 收起后不显示历史 n/m 与模式文案；方向键浏览仍可用；`Cmd+E` 仍生效。
- 持久化按设备全局，不按会话。

## 4. 边界与失败模式

| 场景 | 处理 |
|---|---|
| 输入法组合态按方向键 | 放行，不改草稿 |
| `/`、`@` 菜单打开 | 放行（浏览器方向键归菜单） |
| claim / adjudicating / submitting / sending | 放行（不浏览、不记录） |
| 提交失败 / Host 拒绝 | 无新 pending 条目，不落历史；草稿保留 |
| 提交纯附件、空文字 | 不记录 |
| 提交以 `/` 开头的命令 | 不记录 |
| 历史为空时按 ↑ | 放行给原生光标 |
| 浏览中切换到最旧再按 ↑ | 循环到最新 |
| 浏览中按 ↓ 越过最新 | 还原浏览前草稿并退出 |
| 浏览中打字 / 粘贴 / 剪切 | 退出浏览，保留当前文字 |
| 浏览中提交 | 退出浏览，新消息按正常流程记录 |
| localStorage 不可用 / 配额满 | 历史降级为内存态，不影响其它功能 |
| 历史文档损坏 | 归一为空，不抛错 |
| 单条超长（> 16k 字符） | 跳过记录，避免撑爆配额 |
| 会话切换时正在发送 | 丢弃未确认捕获，不写错数据 |
| 多窗口同时使用 | 各自内存态，刷新后以最后写入者为准（本轮不做 `storage` 事件同步，README 记为限制） |
| 插件禁用 / 卸载 | 组件 effect 移除 keydown/paste 监听；store 随模块卸载；历史留在 localStorage |
| rc.3 环境安装 0.2.0 | 无 `sending` 相位，历史不记录；收起与方向键仍可用，不崩溃 |
