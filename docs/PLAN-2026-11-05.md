## 0. 背景与结论

以 [docs/COMPAT-2026-11-05-dsh-0.2.2-rc.1.md](COMPAT-2026-11-05-dsh-0.2.2-rc.1.md) 的源码级核查为起点，重新对着 0.2.2-rc.1 的源码逐项验证「插件需要改什么」。结论：

- **1 处真回归必须改代码**：`sending` 相位期间多行高度塌陷。
- 其余是安装门禁 / 版本矩阵 / 文档 / 站点，不改交互逻辑。
- 本次发 **0.2.1**（兼容修复版），交互能力与 0.2.0 相同；语言包不做，留给后续版本。

### 关键证据（源码级）

| 事实 | 证据（DSH 0.2.2-rc.1 源码） |
|---|---|
| 普通消息进入 `sending` 冻结相位 | `input/machine.ts`：`send()` 置 `phase='sending'`，`sink-settled` 成功才 `commit-draft` 清空；失败保持草稿 |
| 该相位编辑器只读 | `skeleton/InputBar.tsx`：`machineBusy` 含 `'sending'`，`editable = live && !locked && !machineBusy`；`ComposerContentEditable.tsx`：`contentEditable={editor !== null && editable}` |
| 于是 `contenteditable` 变 `"false"` | React 渲染布尔 `contentEditable` 为 `"true"` / `"false"` |
| 插件的 4 行下限只匹配 `"true"` | 0.2.0 `client.js`：`[data-composer-input][contenteditable="true"]`（主规则 + `@supports` 回退两处） |
| 宿主输入框默认只有 36px | `InputBar.module.css`：`.input { min-height: 36px }`（`.hero .input` 为 52px） |
| 引用（quote）不影响历史内容 | `QuoteNode.getTextContent()` 返回 `formatQuoteText()`；`input/editor/projection.ts` 把 quote 计入 `clipboardText`，即草稿字符串含 `> 原文` |
| 菜单锚点新增稳定属性 | `ui-input-trigger/src/client/MenuView.tsx`：`MenuSurface` 带 `data-trigger-menu`，内部 viewport 仍 `role="listbox"` |
| 兼容门禁只读 `engines.dsh` | `@deepseek-ai/dsh-app-boot` 的 `evaluatePluginCompatibility()`；`satisfies()` 带 `{ includePrerelease: true }` |

## 1. 改动范围（已批准）

### 1.1 代码（client.js）

1. 多行下限选择器改为同时覆盖只读提交相位：

   ```js
   const FLOOR_SELECTOR = `html[${MODE_ATTRIBUTE}="multi"] [data-composer-card] [data-composer-input]:is([contenteditable="true"], [data-phase]:not([data-phase="plain"]))`
   ```

   - 主规则与 `@supports not (height: 1lh)` 回退两处共用该常量。
   - 无 Session 的 Workspace picker 保持 `data-phase="plain"` / 无相位，不会被匹配。
2. 菜单判定改用 `data-trigger-menu`，保留 `[role="listbox"]` 兼容：`TRIGGER_MENU = ':is([data-trigger-menu], [role="listbox"])'`，抽 `menuOpenIn(card)`。
3. 头注释基线更新到 `0.2.2-rc.1`（`66491b05`），列出新增契约点（`machine.ts` / `QuoteNode` / `ComposerContentEditable` / `MenuView`）。
4. `__test` 导出 `FLOOR_SELECTOR` / `TRIGGER_MENU` / `CSS` 供回归测试。

## 2. 验收要点（子龙本机，DSH 0.2.2-rc.1 桌面版）

- 多行模式下发送：输入框**不再**先塌成 1 行再弹回（重点）。
- 多行 Enter 换行 / Shift+Enter 发送；单行保持原生。
- 发送期间（`sending`）Enter / ↑↓ 历史不触发；被拒 / 失败后草稿仍在、不进历史。
- `↑` 召回上一条；带引用发送后 `↑` 召回内容符合预期（引用降级为纯文本）。
- `/`、`@` 菜单打开时 Enter 选中菜单项（验证 `data-trigger-menu` 锚点）。
- 设置页、tab 收起/展开、快捷键改键、模式持久化。

## 3. 实施记录 / 与计划的差异

- **`dshReleases` 未列入 `0.2.1-rc.3`**：计划里写了 rc.3，但落实 `engines.dsh = ">=0.2.1-rc.5 …"` 后 rc.3 会被装前门禁拒绝，两者矛盾；按「0.2.0 起兼容下限就是 rc.5」的既成事实，最终只列 `0.2.1-rc.5` 与 `0.2.2-rc.1`，并在 README 明确 rc.3 及更早不在支持范围。
- **未清理 CSS 模板里的一段历史重复**：`@supports not (height: 1lh)` 块内重复了插件设置页的 `.dmi-settings*` 规则（顶层已有一份，功能无影响）。本次为聚焦兼容修复未动，留待后续顺手清理。
- **语言包未做**：按批准范围，ja/es/fr/de/ru/pt 留到后续版本。
- **版本号链接**：README 顶部 `Release v0.2.0` 链接与 ROADMAP 的 GitHub Release 行留到发布步骤再改（验收前不动线上链接）。
